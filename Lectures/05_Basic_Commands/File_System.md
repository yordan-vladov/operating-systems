## Файлове и директории

---
### Какво е файл?

- **Именувана** последователност от байтове, съхранена на устройство за данни
- Основната единица, в която се пазят данни — документи, програми, снимки, конфигурации
- Операционната система **не налага вътрешна структура** — значението на байтовете се определя от програмата, която ги чете
- Освен съдържанието си, всеки файл има и **метаданни** — размер, собственик, права, дати на последен достъп и промяна
- Разширението (`.txt`, `.png`) е само част от името — Linux **не разчита** на него, за да определи типа

---
### Какво е директория?

- **Специален файл**, който съдържа списък от други файлове и директории
- Всеки запис свързва **име** с конкретен файл
- Директориите могат да се влагат една в друга — така се образува **дървовидна структура**
- Позната още като **папка** (folder) в графичните среди
- Всяка директория съдържа два специални записа:
    - `.` — самата директория
    - `..` — родителската директория

```bash
$ ls -a /home/ivan
.  ..  Documents  Downloads  notes.txt
```

---
## Какво е файлова система?

- Начинът, по който операционната система **организира, съхранява и намира** данните на диска
- Определя:
    - как се именуват файловете
    - къде физически се записват данните
    - какви метаданни се пазят (размер, собственик, права, дати)
    - как се възстановяват данните след срив

---
### Две значения на „файлова система“

- **Структурата от директории**, която потребителят вижда (`/`, `/home`, `/etc` ...)
- **Форматът на данните** върху конкретен диск или дял (ext4, XFS, FAT32 ...)
- В Linux всички дискове и дялове се „закачат“ в **едно общо дърво**

---
## Основна структура

---
### Дървовидна структура

- Всичко започва от **root директорията** — `/`
- Няма букви на дискове като в Windows (`C:\`, `D:\`)
- Всеки файл и директория има **единствен пълен път** от `/`

```text
/
├── bin
├── boot
├── dev
├── etc
├── home
│   ├── ivan
│   └── maria
├── root
├── tmp
├── usr
│   ├── bin
│   └── lib
└── var
    └── log
```

---
### Filesystem Hierarchy Standard (FHS)

- Стандарт, който определя **коя директория за какво служи**
- Поддържа се от Linux Foundation
- Благодарение на него различните дистрибуции имат сходна структура
- Така програмите и администраторите знаят къде да търсят конфигурации, логове, програми и т.н.

---
### Абсолютни и относителни пътища

- **Абсолютен път** — започва от `/`
    - `/home/ivan/Documents/notes.txt`
- **Относителен път** — спрямо текущата директория
    - `Documents/notes.txt`
    - `../maria/file.txt`
- Разделителят е `/` (а не `\` като в Windows)

```bash
$ pwd
/home/ivan
$ cat Documents/notes.txt            # относителен
$ cat /home/ivan/Documents/notes.txt # абсолютен
```

## Системни директории

---
### Обзор

| Директория | Предназначение                                          |
| ---------- | ------------------------------------------------------- |
| `/`        | Корен на цялата файлова система                         |
| `/bin`     | Основни потребителски програми                          |
| `/sbin`    | Системни програми за администрация                      |
| `/boot`    | Файлове за стартиране на системата                      |
| `/dev`     | Файлове на устройства                                   |
| `/etc`     | Конфигурационни файлове                                 |
| `/home`    | Домашни директории на потребителите                     |
| `/root`    | Домашна директория на root                              |
| `/lib`     | Споделени библиотеки и модули на ядрото                 |
| `/usr`     | Инсталиран софтуер (програми, библиотеки, документация) |
| `/var`     | Променливи данни — логове, кеш, опашки                  |
| `/tmp`     | Временни файлове                                        |
| `/opt`     | Допълнителен софтуер от трети страни                    |
| `/media`   | Автоматично монтирани преносими устройства              |
| `/mnt`     | Временно ръчно монтиране                                |
| `/proc`    | Информация за процесите и ядрото (виртуална)            |
| `/sys`     | Информация за хардуера и драйверите (виртуална)         |
| `/run`     | Данни за текущата сесия от стартирането насам           |
| `/srv`     | Данни, обслужвани от сървъри (web, ftp)                 |

---
### /bin и /sbin

- `/bin` — **binaries**, основни команди, нужни на всички потребители
    - `ls`, `cp`, `mv`, `cat`, `bash`
- `/sbin` — **system binaries**, команди за администрация
    - `fdisk`, `mkfs`, `reboot`, `ip`
- В съвременните дистрибуции те често са **линкове** към `/usr/bin` и `/usr/sbin` (т.нар. *usr merge*)

```bash
$ ls -l /bin
lrwxrwxrwx 1 root root 7 Apr 20 10:00 /bin -> usr/bin
```

---
### /boot

- Файлове, нужни за **стартиране** на системата
    - ядрото — `vmlinuz-*`
    - началният RAM диск — `initrd.img-*`
    - конфигурация на bootloader-а — `/boot/grub/`
- Често е на **отделен дял**
- Не пипайте тук, ако не знаете какво правите — системата може да не стартира

---
### /dev

- **Devices** — файлове, представящи устройствата
- Принцип: „в Linux **всичко е файл**“
- Примери:
    - `/dev/sda`, `/dev/nvme0n1` — дискове
    - `/dev/tty` — терминал
    - `/dev/null` — „черна дупка“
    - `/dev/random` — генератор на случайни данни
- Разгледано подробно в урока за **Устройства**

---
### /etc

- Конфигурационни файлове на системата и програмите
- Обикновено са **текстови** файлове — редактират се с `nano`, `vim` и т.н.
- Примери:
    - `/etc/passwd` — потребители
    - `/etc/group` — групи
    - `/etc/hostname` — име на машината
    - `/etc/fstab` — кои дялове се монтират при стартиране
    - `/etc/apt/` — настройки на пакетния мениджър

```bash
$ cat /etc/hostname
my-laptop
```

---
### /usr

- **Unix System Resources** — най-голямата директория
- Съдържа инсталирания софтуер, който **само се чете**
    - `/usr/bin` — програми
    - `/usr/lib` — библиотеки
    - `/usr/share` — документация, икони, man страници
    - `/usr/local` — софтуер, компилиран и инсталиран ръчно от администратора

---
### /var

- **Variable** — данни, които **се променят** по време на работа
    - `/var/log` — лог файлове
    - `/var/cache` — кеш (напр. изтеглени пакети)
    - `/var/lib` — данни на програми (бази данни, Docker ...)
    - `/var/spool` — опашки (печат, поща, cron)
    - `/var/www` — често файловете на уеб сървъра
- Ако дискът се препълни — обикновено виновникът е тук

---
### /tmp

- Временни файлове
- Всеки потребител може да пише тук
- Съдържанието се **изтрива** при рестарт (или периодично)
- Има специален **sticky bit** — потребителят може да трие само своите файлове

```bash
$ ls -ld /tmp
drwxrwxrwt 12 root root 4096 Apr 20 10:00 /tmp
```

---
### /lib

- Споделени библиотеки (`.so` — *shared objects*), нужни на програмите в `/bin` и `/sbin`
- Аналог на `.dll` файловете в Windows
- `/lib/modules/` — модули (драйвери) на ядрото

---
### /opt, /media, /mnt, /srv

- `/opt` — **optional**, самостоятелни програми от трети страни (напр. Google Chrome)
- `/media` — тук системата автоматично монтира USB памети, дискове
    - `/media/ivan/MY_USB`
- `/mnt` — за временно ръчно монтиране от администратора
- `/srv` — данни, които сървърите предоставят навън

---
### /proc и /sys

- **Виртуални** файлови системи — не съществуват на диска
- Създават се от ядрото **в паметта**
- `/proc` — информация за процеси и ядрото
    - `/proc/<PID>/` — директория за всеки процес
    - `/proc/cpuinfo`, `/proc/meminfo`
- `/sys` — информация за хардуера, драйверите, устройствата

```bash
$ cat /proc/cpuinfo | grep "model name"
$ cat /proc/meminfo | head -3
```

---
### /run

- Данни за **текущото** стартиране на системата
    - PID файлове на демоните
    - сокети
- Намира се в RAM паметта и се изчиства при рестарт

## Home директории

---
### Какво е home директория?

- Лична директория на всеки потребител
- Намира се в `/home/<потребител>`
- Тук потребителят има **пълни права**
- Тук се пазят личните файлове и **личните настройки** на програмите
- Изключение: домашната директория на **root** е `/root`

```bash
$ echo $HOME
/home/ivan
```

---
### Бърз достъп до home

- `~` — съкращение за домашната директория на текущия потребител
- `~maria` — домашната директория на потребителя `maria`
- `cd` без аргументи — връща в home

```bash
$ cd ~/Documents
$ ls ~maria
$ cd
$ pwd
/home/ivan
```

---
### Типично съдържание

```text
/home/ivan
├── Desktop
├── Documents
├── Downloads
├── Music
├── Pictures
├── .bashrc
├── .profile
├── .ssh/
├── .config/
└── .cache/
```

---
### Скрити файлове (dotfiles)

- Файлове и директории, чието име започва с `.`, са **скрити**
- Обикновено съдържат настройки
    - `.bashrc` — настройки на Bash
    - `.ssh/` — SSH ключове
    - `.config/` — настройки на програмите
- Показват се с `ls -a`

```bash
$ ls -a ~
.  ..  .bashrc  .profile  .ssh  Desktop  Documents
```

---
### Създаване на home директория

- При създаване на нов потребител с `useradd -m` или `adduser` се създава home директория
- Съдържанието ѝ се копира от шаблона `/etc/skel`
- Разгледано в урока за **Потребители и групи**

```bash
$ sudo useradd -m pesho
$ ls -a /home/pesho
.  ..  .bash_logout  .bashrc  .profile
```

---
### Защо home е отделно?

- Личните данни са **отделени** от системата
- `/home` може да е на **отделен дял**
    - при преинсталиране на системата данните остават
- Лесно архивиране — достатъчно е да се копира `/home`
- Потребителите не могат да си пречат един на друг

## Основни характеристики

---
### Всичко е файл

- Обикновените файлове, директориите, устройствата, процесите, сокетите — всички се представят като файлове
- Така с едни и същи команди (`cat`, `echo`, `ls`) може да се работи с много различни ресурси

```bash
$ echo "hello" > /dev/null
$ cat /proc/uptime
```

---
### Видове файлове

- Първият символ в `ls -l` показва вида на файла

| Символ | Вид                   |
| ------ | --------------------- |
| `-`    | Обикновен файл        |
| `d`    | Директория            |
| `l`    | Символен линк         |
| `b`    | Блоково устройство    |
| `c`    | Символно устройство   |
| `p`    | Именуван канал (pipe) |
| `s`    | Сокет                 |

```bash
$ ls -l /dev/sda /dev/null
brw-rw---- 1 root disk 8, 0 Apr 20 10:00 /dev/sda
crw-rw-rw- 1 root root 1, 3 Apr 20 10:00 /dev/null
```

---
### Имена на файлове

- **Чувствителни към малки и главни букви**
    - `File.txt`, `file.txt` и `FILE.TXT` са три различни файла
- Разширенията **не са задължителни**
    - типът на файла се определя от съдържанието, а не от името
- Могат да съдържат почти всички символи, освен `/` и `\0`
- Избягвайте интервали и специални символи — трябва да се ограждат с кавички

```bash
$ touch "my file.txt"
$ ls my\ file.txt
```

---
### Inode

- Всеки файл има **inode** — структура с метаданните му:
    - размер
    - собственик и група
    - права за достъп
    - дати на създаване, промяна, достъп
    - къде се намират данните на диска
- **Името на файла не е в inode-а** — то се пази в директорията
- Затова един файл може да има няколко имена (твърди линкове)

```bash
$ ls -i file.txt
1573020 file.txt
```

---
### Права за достъп

- Всеки файл има собственик, група и права (`r`, `w`, `x`)
- Защитават системните файлове от обикновените потребители
- Разгледано подробно в урока за **Права за достъп**

```bash
$ ls -l /etc/shadow
-rw-r----- 1 root shadow 1234 Apr 20 10:00 /etc/shadow
```

---
### Монтиране

- Всеки диск/дял се **монтира** (закача) към директория от общото дърво
- Тази директория се нарича **точка на монтиране** (mount point)
- Потребителят не вижда къде физически са данните
    - `/` може да е на SSD
    - `/home` на друг диск
    - `/media/ivan/USB` на флашка
- Постоянните монтирания се описват в `/etc/fstab`

---
### Virtual File System (VFS)

- Слой в ядрото, който скрива разликите между файловите системи
- Програмите използват едни и същи системни извиквания (`open`, `read`, `write`) независимо дали файлът е на ext4, FAT32, в мрежата или в `/proc`

## Инструменти

---
### tree

- Показва директориите като дърво
- Може да се наложи да се инсталира (`sudo apt install tree`)
- `-L` — ограничава дълбочината

```bash
$ tree -L 1 /
/
├── bin -> usr/bin
├── boot
├── dev
├── etc
...
```

---
### stat

- Показва подробни метаданни за файл (информацията от inode-а)

```bash
$ stat notes.txt
  File: notes.txt
  Size: 1024        Blocks: 8          IO Block: 4096   regular file
Device: 8,1         Inode: 1573020     Links: 1
Access: (0644/-rw-r--r--)  Uid: ( 1000/ ivan)   Gid: ( 1000/ ivan)
Modify: 2026-04-20 10:00:00.000000000 +0300
```

---
### file

- Определя **типа на файла по съдържанието му**, а не по разширението

```bash
$ file notes.txt
notes.txt: ASCII text
$ file /bin/ls
/bin/ls: ELF 64-bit LSB pie executable, x86-64 ...
$ file picture
picture: PNG image data, 800 x 600
```

---
### df

- **Disk Free** — показва свободното място по файлови системи
- `-h` — четим формат
- `-T` — показва и типа на файловата система

```bash
$ df -hT
Filesystem     Type   Size  Used Avail Use% Mounted on
/dev/sda2      ext4    98G   40G   53G  43% /
/dev/sda1      vfat   512M  6.1M  506M   2% /boot/efi
tmpfs          tmpfs  3.9G     0  3.9G   0% /tmp
```

---
### du

- **Disk Usage** — показва колко място заемат файлове и директории
- `-h` — четим формат
- `-s` — само обща сума

```bash
$ du -sh ~/Downloads
2.3G    /home/ivan/Downloads

$ du -h --max-depth=1 /var | sort -h
```

---
### lsblk

- Показва дисковете и дяловете като дърво
- `-f` — показва и файловата система

```bash
$ lsblk -f
NAME   FSTYPE LABEL UUID      MOUNTPOINTS
sda
├─sda1 vfat         1A2B-3C4D /boot/efi
└─sda2 ext4         a1b2c3... /
sdb
└─sdb1 exfat  USB   5E6F-7A8B /media/ivan/USB
```

---
### mount и findmnt

- `mount` — монтира файлова система / показва монтираните
- `umount` — демонтира
- `findmnt` — показва монтираните файлови системи като дърво

```bash
$ sudo mount /dev/sdb1 /mnt
$ findmnt /
TARGET SOURCE    FSTYPE OPTIONS
/      /dev/sda2 ext4   rw,relatime
$ sudo umount /mnt
```

---
### mkfs и fsck

- `mkfs` — **make file system**, създава файлова система (форматира)
- `fsck` — **file system check**, проверява и поправя грешки
- И двете се изпълняват върху **демонтиран** дял

```bash
$ sudo mkfs.ext4 /dev/sdb1
$ sudo fsck /dev/sdb1
```

## Видове файлови системи в Linux

---
### Дискови файлови системи — Linux

| Файлова система | Характеристики                                                    |
| --------------- | ----------------------------------------------------------------- |
| **ext4**        | Стандарт в Debian/Ubuntu, журнализация, стабилна и универсална    |
| **XFS**         | Стандарт в RHEL/Fedora Server, много добра при големи файлове     |
| **Btrfs**       | Стандарт във Fedora/openSUSE, snapshots, компресия, copy-on-write |
| **ZFS**         | Сървъри и NAS, snapshots, RAID, проверка за цялост на данните     |
| **F2FS**        | Оптимизирана за флаш памети (SSD, SD карти, телефони)             |

---
### ext4

- **Fourth Extended File System**
- Най-разпространената Linux файлова система
- Журнализация — по-малък риск от загуба на данни при срив
- Файлове до 16 TB, дялове до 1 EB
- Наследник на ext2 и ext3

---
### Btrfs и ZFS

- Модерни файлови системи с **copy-on-write**
    - данните не се презаписват, а се записват на ново място
- **Snapshots** — моментна „снимка“ на системата, към която може да се върнем
- Вградена компресия
- Проверка за цялост на данните (checksums)
- Управление на няколко диска (RAID)

---
### Файлови системи за съвместимост

| Файлова система | Употреба                                                  |
|-----------------|-----------------------------------------------------------|
| **FAT32 (vfat)**| USB памети, EFI дял; файлове до 4 GB                      |
| **exFAT**       | USB памети и SD карти; без ограничението от 4 GB          |
| **NTFS**        | Windows дискове                                           |
| **ISO 9660**    | CD/DVD и `.iso` образи                                    |

- Разгледани в урока за **Устройства**

---
### Виртуални файлови системи

- Не се намират на диск, а се създават от ядрото
- **proc** — `/proc`, процеси и ядро
- **sysfs** — `/sys`, хардуер и драйвери
- **devtmpfs** — `/dev`, файлове на устройства
- **tmpfs** — файлова система в **RAM паметта**
    - много бърза
    - изчезва при рестарт
    - използва се за `/tmp`, `/run`

---
### Мрежови файлови системи

- Позволяват достъп до файлове на друг компютър, сякаш са локални
- **NFS** — Network File System, стандарт в Unix/Linux
- **SMB/CIFS** — споделени папки от Windows (Samba)
- **SSHFS** — монтиране на отдалечена директория през SSH

```bash
$ sudo mount -t nfs server:/shared /mnt/shared
```

---
### Swap

- Специален дял или файл, който не е файлова система в обичайния смисъл
- Използва се като **допълнение към RAM паметта**
- Когато RAM паметта свърши, ядрото премества неизползвани страници в swap

```bash
$ swapon --show
NAME      TYPE SIZE USED PRIO
/swapfile file   2G   0B   -2
```

---
### Как да видим какви файлови системи използваме?

```bash
$ df -T
$ lsblk -f
$ findmnt
$ cat /proc/filesystems   # поддържаните от ядрото
```
