# Разрешения

---
## Разрешения

- "Правата", които имаме върху даден файл/директория. Делят се на три основни вида:
    - **read**
    - **write**
    - **execute**
- Често се наричат "пермишъни" (permission)
---
## READ

- Позволява ни да видим съдържанието на файл или директория.
- По подразбиране можем да четем по-голямата част от файловата система

---
## WRITE

- Позволява ни да променяме съдържанието на файл или директорията
- При директориите това включва добавяне или триене на файлове
- По подразбиране имаме **write** позволения върху нашата **home** директория

---
## EXECUTE

- За файлове ни позволява да изпълним програмата/скрипта която се намира във файла
- За директории ни позволява да навигираме към нея и да достъпваме нейното съдържание

---

## Извеждане на позволения

- Използваме `ls -l <file/directory>`
- Пример:
```bash
ls -l /etc/passwd
-rw-r--r-- 1 root root 3255 Aug 24 11:59 /etc/passwd
```

## chmod

- Позволява ни да променим разрешенията за даден файл или директория
- И има два основни формата за задаване на разрешения:
    - символно
    - числено (октално)

---
## Символно задаване

- Трябва да определим:
    - За **Кого** определяме разрешенията
    - **Каква** промяна извършваме
    - **Кои** разрешения задаваме

---
## chmod - Кого

- "u" - Потребител
- "g" - Група
- "o" - Други
- "a" - Всички

---
## chmod - Каква промяна

- "=" - Задаваме нови разрешения
- "+" - Добавяме разрешения
- "-" - Премахваме разрешения

---
## chmod - Кои разрешения

- "r" - Четене
- "w" - Писане
- "x" - Изпълнение

---
## chmod - Примери

```bash
chmod g=rx,o= file_1.txt
chmod u=rwx,g=rw,o= file_2.txt
chmod a=rwx file_3.txt
```

---

```bash
chmod u+x file_1.txt
chmod o+rw file_2.txt
```

---

```bash
chmod u-w file_1.txt
chmod g-rw file_2.txt
chmod a-wx file_2.txt
```

---

## Числено представяне

- Позволенията се представят чрез трицифрено число
- Всяка цифра има стойност от 0-7
- Трите основни разрешения са представени чрез цифрите 1 ('x'), 2 ('w') и 4 ('r')
- Различните комбинации на разрешенията се представят чрез сборове на тези цифри

## Специални разрешения

- Освен **r**, **w** и **x** има още три специални разрешения:
    - **SUID** (Set User ID)
    - **SGID** (Set Group ID)
    - **Sticky bit**
- Те променят **как** се изпълнява програма или **как** се държи директория
- Използват се, когато обикновените разрешения не са достатъчни

---
## Специални разрешения - Обобщение

| Право  | Символ | Октал | Ефект                                            |
| ------ | ------ | ----- | ------------------------------------------------ |
| SUID   | `s`    | 4000  | Изпълнява се с правата на **собственика**        |
| SGID   | `s`    | 2000  | Изпълнява се с правата на **групата**            |
| Sticky | `t`    | 1000  | Само собственикът може да изтрие файла в папката |

---
## SUID

- Задава се на **изпълними файлове**
- Обикновено програмата работи с правата на потребителя, който я **стартира**
- При SUID програмата работи с правата на **собственика на файла**
- Ако собственикът е **root**, програмата временно получава root права
- Символът `s` се появява на мястото на `x` за собственика

---
## SUID - Пример

- Паролите се пазят в `/etc/shadow`, който може да се променя само от root
- Всеки потребител обаче може да смени паролата си с `passwd`
- Това е възможно, защото `passwd` има SUID и се изпълнява като root

```bash
ls -l /usr/bin/passwd
-rwsr-xr-x 1 root root ... /usr/bin/passwd

ls -l /etc/shadow
-rw-r----- 1 root shadow ... /etc/shadow
```

- Други примери: `sudo`, `su`, `mount`

---
## SGID

- **При файлове** - програмата се изпълнява с правата на **групата** на файла
- **При директории** - всички нови файлове в директорията наследяват **групата на директорията**, а не основната група на създателя
- Символът `s` се появява на мястото на `x` за групата

---
## SGID - Пример

- Използва се най-често за **споделени директории** на екип
- Всички членове на групата `dev` могат да работят с файловете на останалите

```bash
mkdir /srv/project
chgrp dev /srv/project
chmod 2775 /srv/project

ls -ld /srv/project
drwxrwsr-x 2 root dev ... /srv/project

touch /srv/project/notes.txt   # създаден от alice
ls -l /srv/project/notes.txt
-rw-rw-r-- 1 alice dev ... notes.txt   # групата е dev, а не alice
```

---
## Sticky bit

- Задава се на **директории**
- Нормално, ако имаме **write** право върху директория, можем да трием **всеки** файл в нея
- При sticky bit файл може да бъде изтрит или преименуван само от:
    - собственика на файла
    - собственика на директорията
    - root
- Символът `t` се появява на мястото на `x` за другите

---
## Sticky bit - Пример

- `/tmp` е достъпна за писане от всички потребители
- Без sticky bit всеки би могъл да изтрие временните файлове на другите

```bash
ls -ld /tmp
drwxrwxrwt 20 root root ... /tmp
```

---
## Главни букви `S` и `T`

- Ако специалното право е зададено, но **липсва** `x`, се показва главна буква
- Това обикновено означава грешка в настройките - специалното право няма ефект

```bash
-rwSr--r--  # SUID без x за собственика
drwxrwxrwT  # Sticky bit без x за другите
```

---
## Задаване на специални разрешения

```bash
# Символно
chmod u+s file      # задава SUID
chmod g+s dir       # задава SGID
chmod +t dir        # задава Sticky bit

# Октално (четвърта цифра пред стандартните права)
chmod 4755 file     # SUID  + rwxr-xr-x
chmod 2755 dir      # SGID  + rwxr-xr-x
chmod 1777 dir      # Sticky + rwxrwxrwx (като /tmp)
chmod 6755 file     # SUID + SGID + rwxr-xr-x
```

---
## Специални разрешения и сигурност

- Програма със SUID root, която има грешка, може да позволи на потребител да получи root достъп
- Затова SUID/SGID трябва да се задават само когато е наистина необходимо
- Полезно е периодично да се проверява кои файлове ги имат:

```bash
# Файлове с SUID
find / -perm -4000 -type f 2>/dev/null

# Файлове с SGID
find / -perm -2000 -type f 2>/dev/null
```

## chown

- Променя собственика/групата на файл/директория

```bash
chown user_1 file_1.txt
chown user_1:group_1 file_1.txt
chown :group_1 file_1.txt
```

---
## chgrp

- Променя групата на файл/директория

```bash
chgrp group file_1.txt
```
