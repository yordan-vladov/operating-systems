## 1. Какво е SSH?

---

### Secure Shell (SSH)

- **SSH** е криптографски мрежов протокол за **сигурна отдалечена комуникация**.
- Заменя незащитени протоколи като `telnet` и `rsh`.
- Работи по подразбиране на **порт 22**.
- Осигурява:
  - **Автентикация** (парола или ключ)
  - **Шифровано** предаване на данни
  - **Цялостност** на пренесените данни

---

### Типични употреби

- Отдалечено управление на сървъри.
- Прехвърляне на файлове (`scp`, `rsync`, `sftp`).
- Тунелиране на мрежов трафик.
- Автоматизация и CI/CD пайплайни.

---

### SSH клиент и сървър

| Компонент    | Пакет              | Команда        |
| ------------ | ------------------ | -------------- |
| SSH клиент   | `openssh-client`   | `ssh`          |
| SSH сървър   | `openssh-server`   | `sshd` (демон) |

```bash
# Инсталиране на сървъра (Debian/Ubuntu)
sudo apt install openssh-server

# Проверка на статуса
sudo systemctl status ssh
```

## 2. Основна употреба на `ssh`

---

### Свързване към отдалечен хост

```bash
# Базово свързване
ssh потребител@хост

# Примери
ssh admin@192.168.1.50
ssh yordan@server.example.com

# Указване на порт (ако не е 22)
ssh -p 2222 yordan@server.example.com
```

---

### Изпълнение на команда без интерактивна сесия

```bash
# Изпълнява командата и се разкачва
ssh yordan@server.example.com "uptime"

# Изпълнява няколко команди
ssh yordan@server.example.com "df -h && free -m"
```

---

### Конфигурационен файл `~/.ssh/config`

Позволява дефиниране на псевдоними за хостове, за да не се въвеждат параметрите всеки път.

```
Host моя-сървър
    HostName 192.168.1.50
    User yordan
    Port 2222
    IdentityFile ~/.ssh/id_ed25519
```

```bash
# Сега можем просто да пишем:
ssh моя-сървър
```

## 3. SSH ключове

---

### Защо ключове вместо пароли?

| Метод   | Сигурност                       | Удобство                       |
| ------- | ------------------------------- | ------------------------------ |
| Парола  | Уязвима на brute-force           | Трябва да се въвежда ръчно     |
| SSH ключ | Практически невъзможна за разбиване | Автоматична автентикация |

- SSH ключът се основава на **асиметрична криптография**.
- Генерира се **двойка ключове**: **частен** (таен) и **публичен**.

---

### Как работят ключовете?

```
┌──────────────────┐           ┌──────────────────┐
│     Клиент       │           │      Сървър      │
│                  │           │                  │
│  частен ключ 🔑  │──────────▶│  публичен ключ 🔓 │
│  (само при теб)  │   SSH     │  (~/.ssh/        │
│                  │  връзка   │  authorized_keys) │
└──────────────────┘           └──────────────────┘
```

- Публичният ключ се копира на сървъра.
- Частният ключ **никога не напуска** клиентската машина.

---

### Генериране на SSH ключ

```bash
# Препоръчван алгоритъм: Ed25519 (по-бърз и по-сигурен от RSA)
ssh-keygen -t ed25519 -C "yordan@example.com"

# По-стар, но широко поддържан RSA ключ (4096 бита)
ssh-keygen -t rsa -b 4096 -C "yordan@example.com"
```

---

### По-подробно генериране

```
Generating public/private ed25519 key pair.
Enter file in which to save the key (/home/yordan/.ssh/id_ed25519):
Enter passphrase (empty for no passphrase): ••••••••
Enter same passphrase again: ••••••••
Your identification has been saved in /home/yordan/.ssh/id_ed25519
Your public key has been saved in /home/yordan/.ssh/id_ed25519.pub
```

- `~/.ssh/id_ed25519` — **частен ключ** (chmod 600, само за четене от собственика!)
- `~/.ssh/id_ed25519.pub` — **публичен ключ** (може да се споделя)

---

### Копиране на публичния ключ към сървъра

```bash
# Автоматичен начин (препоръчан)
ssh-copy-id -i ~/.ssh/id_ed25519.pub yordan@192.168.1.50

# Ръчен начин — добавя ключа към authorized_keys на сървъра
cat ~/.ssh/id_ed25519.pub | ssh yordan@192.168.1.50 \
  "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"
```

---

### Права на файловете за SSH

SSH е **строг към правата** — грешните права причиняват отказ на автентикация.

```bash
# Права на директорията
chmod 700 ~/.ssh

# Права на частния ключ
chmod 600 ~/.ssh/id_ed25519

# Права на публичния ключ
chmod 644 ~/.ssh/id_ed25519.pub

# Права на authorized_keys (на сървъра)
chmod 600 ~/.ssh/authorized_keys
```

## 4. `ssh-agent` — управление на ключове

---

### Проблемът с паролата на ключа

- Когато ключът е защитен с **passphrase** (препоръчително!), трябва да се въвежда при всяка употреба.
- `ssh-agent` **кешира** ключовете в паметта — въвеждаме passphrase само веднъж.

---

### Стартиране и използване на `ssh-agent`

```bash
# Стартиране на агента (ако не е стартиран автоматично)
eval "$(ssh-agent -s)"
# Agent pid 12345

# Добавяне на ключ към агента
ssh-add ~/.ssh/id_ed25519
# Enter passphrase for /home/yordan/.ssh/id_ed25519: ••••••

# Проверка на заредените ключове
ssh-add -l
# 256 SHA256:... yordan@example.com (ED25519)
```

---

### Управление на ключовете в агента

```bash
# Премахване на конкретен ключ
ssh-add -d ~/.ssh/id_ed25519

# Премахване на всички ключове
ssh-add -D

# Задаване на времеви лимит (ключът се изтрива след 1 час)
ssh-add -t 3600 ~/.ssh/id_ed25519
```

---

### SSH Agent Forwarding

Позволява използването на локалните ключове при свързване **от сървър към друг сървър**.

```bash
# Свързване с форуърдинг на агента
ssh -A yordan@jump-server.example.com

# Или в ~/.ssh/config
Host jump-server
    ForwardAgent yes
```

> **Внимание:** Използвайте само на доверени сървъри — администраторът може да злоупотреби с форуърдвания агент.

## 5. SSH тунелиране

---

### Какво е SSH тунел?

- Пренасочване на мрежов трафик **през шифрована SSH връзка**.
- Използва се за:
  - Достъп до услуги зад firewall
  - Шифроване на незащитен трафик
  - Заобикаляне на мрежови ограничения

---

### Локално тунелиране (`-L`)

Пренасочва локален порт към отдалечена дестинация.

```
[Локална машина] ──SSH──▶ [SSH сървър] ──TCP──▶ [Целева услуга]
localhost:8080              server                 db.internal:5432
```

```bash
# Достъп до отдалечена база данни на localhost:8080
ssh -L 8080:db.internal:5432 yordan@server.example.com

# Достъп до уеб интерфейс на отдалечена услуга
ssh -L 8443:localhost:443 yordan@server.example.com
```

---

### Отдалечено тунелиране (`-R`)

Пренасочва порт на **сървъра** към локална услуга.

```
[Интернет потребител] ──▶ [SSH сървър]:9090 ──SSH──▶ [Локална машина]:3000
```

```bash
# Излагане на локален уеб сървър на порт 9090 на сървъра
ssh -R 9090:localhost:3000 yordan@server.example.com
```

Полезно когато локалната машина е зад NAT или firewall.

---

### Динамично тунелиране (SOCKS прокси, `-D`)

Превръща SSH връзката в **SOCKS5 прокси**.

```bash
# Стартира SOCKS прокси на порт 1080
ssh -D 1080 yordan@server.example.com
```

- Настройте браузъра си да използва `SOCKS5` прокси на `localhost:1080`.
- Целият трафик се насочва шифровано през SSH сървъра.

---

### Тунел без интерактивна сесия (`-N -f`)

```bash
# -N: не изпълнява команди (само тунел)
# -f: работи на заден план
ssh -N -f -L 8080:db.internal:5432 yordan@server.example.com
```

## 6. Прехвърляне на файлове — `scp` и `rsync`

---

### `scp` — Secure Copy

- Копира файлове между локална и отдалечена машина.
- Работи като `cp`, но с SSH транспорт.

```bash
# Копиране на локален файл към сървъра
scp файл.txt yordan@server.example.com:/home/yordan/

# Копиране от сървъра към локалната машина
scp yordan@server.example.com:/var/log/syslog ./

# Копиране на директория (рекурсивно)
scp -r ./проект/ yordan@server.example.com:/srv/

# Указване на порт
scp -P 2222 файл.txt yordan@server.example.com:/tmp/
```

---

### Ограничения на `scp`

- **Не поддържа** инкрементално синхронизиране.
- При повторно копиране — **презаписва** целия файл.
- За по-ефективно синхронизиране се използва `rsync`.

---

### `rsync` — Ефективна синхронизация

- Копира само **разликите** между файловете.
- Работи локално и отдалечено (през SSH).
- Поддържа права, символни връзки, timestamps.

```bash
# Синхронизиране на локална директория към сървъра
rsync -avz ./проект/ yordan@server.example.com:/srv/проект/

# Синхронизиране от сървъра към локалната машина
rsync -avz yordan@server.example.com:/srv/backup/ ./backup/
```

---

### Флагове на `rsync`

| Флаг | Значение                                        |
| ---- | ----------------------------------------------- |
| `-a` | Архивен режим (пази права, timestamps, symlinks) |
| `-v` | Подробен изход (verbose)                        |
| `-z` | Компресиране при пренос                         |
| `-n` | Dry run — показва какво би направило             |
| `--delete` | Изтрива файлове на дестинацията, ги няма в изходния |
| `--progress` | Показва прогреса на пренасяне                |
| `-e` | Указва SSH команда (напр. порт)                 |

---

### Примери с `rsync`

```bash
# Dry run — виж какво ще се промени
rsync -avzn ./проект/ yordan@server.example.com:/srv/проект/

# Синхронизиране с изтриване на излишни файлове
rsync -avz --delete ./проект/ yordan@server.example.com:/srv/проект/

# Използване на нестандартен SSH порт
rsync -avz -e "ssh -p 2222" ./данни/ yordan@server.example.com:/backup/

# Изключване на файлове
rsync -avz --exclude="*.log" --exclude=".git" \
  ./проект/ yordan@server.example.com:/srv/проект/
```

---

### `scp` срещу `rsync`

| Критерий              | `scp`          | `rsync`                     |
| --------------------- | -------------- | --------------------------- |
| Скорост при повторен пренос | Бавна   | Бърза (само разликите)      |
| Прекъснат пренос      | Започва отново | Продължава от където е спряло |
| Синхронизиране        | Не             | Да                          |
| Сложност              | Лесен          | По-сложен                   |
| Подходящ за           | Еднократни копия | Backup, синхронизиране    |

## 7. Практически задачи

---

### Задача 1 — Генериране и настройка на SSH ключ

```bash
# 1. Генерирайте Ed25519 ключ
ssh-keygen -t ed25519 -C "вашия@имейл.com"

# 2. Разгледайте генерираните файлове
ls -la ~/.ssh/
cat ~/.ssh/id_ed25519.pub

# 3. Копирайте ключа към VM или друга машина
ssh-copy-id потребител@хост
```

**Цел:** Свържете се без парола.

---

### Задача 2 — `ssh-agent`

```bash
# 1. Стартирайте агента
eval "$(ssh-agent -s)"

# 2. Добавете ключ с времеви лимит от 30 минути
ssh-add -t 1800 ~/.ssh/id_ed25519

# 3. Проверете заредените ключове
ssh-add -l

# 4. Свържете се с хост — passphrase не трябва да се иска
ssh потребител@хост
```

---

### Задача 3 — SSH тунел

```bash
# 1. Стартирайте тунел към уеб сървър на VM
ssh -N -f -L 8080:localhost:80 потребител@vm-хост

# 2. Отворете браузъра на http://localhost:8080

# 3. Намерете и спрете тунела
ps aux | grep ssh
kill <PID>
```

---

### Задача 4 — Синхронизиране с `rsync`

```bash
# 1. Направете dry run
rsync -avzn ~/Documents/ потребител@хост:/backup/documents/

# 2. Изпълнете реалното синхронизиране
rsync -avz ~/Documents/ потребител@хост:/backup/documents/

# 3. Добавете/изтрийте файл локално и синхронизирайте отново с --delete
rsync -avz --delete ~/Documents/ потребител@хост:/backup/documents/
```

## 8. Обобщение

---

### Основни команди

| Команда                             | Предназначение                          |
| ----------------------------------- | --------------------------------------- |
| `ssh user@host`                     | Отдалечена конзола                      |
| `ssh-keygen -t ed25519`             | Генериране на SSH ключ                  |
| `ssh-copy-id user@host`             | Копиране на публичния ключ              |
| `ssh-add ~/.ssh/id_ed25519`         | Зареждане на ключ в ssh-agent           |
| `ssh -L local:host:port user@srv`   | Локален SSH тунел                       |
| `ssh -R remote:host:port user@srv`  | Отдалечен SSH тунел                     |
| `ssh -D 1080 user@host`             | SOCKS прокси тунел                      |
| `scp файл user@host:/path/`         | Копиране на файл към сървър             |
| `rsync -avz src/ user@host:/dst/`   | Инкрементална синхронизация             |

---

### Ключови изводи

- Използвайте **Ed25519 ключове** вместо пароли — по-сигурно и удобно.
- Защитете частния ключ с **passphrase** и използвайте `ssh-agent`.
- `~/.ssh/config` опростява работата с много хостове.
- SSH тунелите позволяват защитен достъп до услуги зад firewall.
- Предпочитайте `rsync` пред `scp` при синхронизиране на директории.
