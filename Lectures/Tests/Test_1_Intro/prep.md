## 1. Хардуер (Увод)

### Процесор

- **Контролна единица** - управлява изпълнението на инструкциите
- **ALU** (аритметико-логическа единица) - смята
- **Регистри** - най-бързата памет, вътре в процесора
	- **PC** (програмен брояч) - адресът на *следващата* инструкция
	- **IR** (регистър на инструкциите) - *текущата* инструкция
- Компонентите са свързани чрез **шини**
- **Data path** - регистрите, ALU и шините между тях (два входни регистъра, един изход)
- Видове инструкции:
	- **регистър-памет** - взима думи от паметта или ги връща
	- **регистър-регистър** - операнди от регистрите → операция → резултат

### Fetch-Decode-Execute (7 стъпки)

1. Извлечи следващата инструкция от паметта и я сложи в IR
2. Промени PC да сочи към следващата инструкция
3. Определи типа на инструкцията
4. Ако ползва дума от паметта - определи къде е
5. Извлечи думата (ако е нужно) и я сложи в регистър
6. Изпълни инструкцията
7. Върни се на стъпка 1

### Прекъсвания

- Сигнал към процесора, че има събитие, което иска незабавно внимание
- Източник: **хардуер** (I/O устройство, таймер) или **софтуер** (грешка, системно повикване)
- Проверява се **след всяка изпълнена инструкция**
- Обработка:
	1. Процесорът запазва състоянието си (регистри, PC)
	2. Скача към **interrupt handler** за конкретното прекъсване
	3. Handler-ът се изпълнява
	4. Състоянието се възстановява и изпълнението продължава оттам, където е спряло

### Памет

| Понятие | Какво е |
| ------- | ------- |
| Бит | 0 или 1, основната единица |
| Клетка | има адрес; n клетки → адреси 0..n-1; клетка с k бита → 2^k стойности |
| Адрес с m бита | 2^m адресируеми клетки (12 бита → 2^12 = 4096 клетки) |
| Байт | 8 бита, най-малката адресируема единица |
| Дума | 32-битова = 4 байта, 64-битова = 8 байта; размерът на регистрите |

> Бързо смятане: 2^8 = 256, 2^10 = 1024, 2^12 = 4096, 2^16 = 65 536, 2^32 ≈ 4 милиарда

**Йерархия (бърза/скъпа/малка → бавна/евтина/голяма):**
регистри → кеш → RAM → HDD/SSD

- **Кеш** - между процесора и RAM; работи на принципа на **локалността**
- **RAM** - волатилна (губи данните без ток), произволен достъп
- **Вторична памет** (HDD/SSD) - трайна, бавна, голяма, евтина

### Вход-изход

- Всяко I/O устройство има **контролер**, чрез който комуникира с компютъра

### Шини

| Шина | Роля |
| ---- | ---- |
| Адресна | *къде* в паметта се чете/пише |
| Данни | *какво* се чете/пише |
| Контролна | четене или запис, и *кога* |

- **Множество шини** - една шина е „тясно гърло“; има йерархия, свързана с **мостове (bridges)**
- **Пропускателна способност ≈ ширина × честота**
- **Арбитраж** - само едно устройство ползва шината в даден момент; **арбитърът** избира „master“-а
- Примери: **PCIe** (карти), **USB** (периферия), **SATA** (дискове)

## 2. Какво е операционна система

### Защо ни трябва ОС - 3 проблема

| Проблем | Решение от ОС |
| ------- | ------------- |
| Сложност - хардуерът е труден и различен | **опростява** (абстракция): файлове вместо блокове, адресно пространство вместо физическа памет, процеси вместо процесор |
| Споделяне - много програми, малко ресурси | **разпределя** ресурсите (арбитър за целия компютър) |
| Защита - грешни/зловредни програми | **изолира**: потребителски и привилегирован режим |

### Определение

- Софтуер, който управлява хардуера и стои между програмите и хардуера
- Две гледни точки:
	- **разширена машина** (отгоре надолу) - удобна абстракция
	- **мениджър на ресурси** (отдолу нагоре) - разпределя процесор, памет, диск, устройства

| | |
| - | - |
| **Ядро** | програмата, която управлява хардуера (Linux) |
| **ОС** | ядро + основни програми и библиотеки |
| **Дистрибуция** | ядро + програми + инсталатор (Ubuntu, Debian, Fedora) |

- Android използва Linux ядрото, но с друга потребителска част

### История и видове ОС

- Без ОС → **пакетна обработка** → **мултипрограмиране** (докато една чака I/O, друга работи) → **разделяне на времето**
- Видове: пакетни, с разделяне на времето, **RTOS** (гарантиран срок), вградени, мобилни, разпределени

### Стартиране

**фърмуер (BIOS/UEFI) → boot loader (GRUB) → ядро → първата потребителска програма**

- **Фърмуер** - във флаш памет на дънната платка; проверява хардуера, намира устройство за стартиране; *не* предлага системни извиквания
- **Boot loader** - на диска; зарежда ядрото в паметта и предава управлението; после повече не участва
- Слоеве: хардуер → ОС (ядро) → приложения → потребител

### Виртуализация

- Физически ресурс → по-проста и „щедра“ виртуална форма
- Интерфейсът към програмите са няколкостотин **системни извиквания**; обикновено през **libc**

**Програма vs процес**
- **Програма** - пасивен изпълним файл на диска
- **Процес** - изпълняваща се програма (памет, регистри, отворени файлове)
- Една програма → много процеси

**Виртуализация на процесора**
- **Time sharing** - процесорът се дава на процес за милисекунди, после **context switch**
- **Планировчик (scheduler)** - решава кой процес работи
- **Таймерно прекъсване** - хардуерният таймер връща управлението на ядрото → безкраен цикъл не блокира системата
- Пример `./cpu A & ./cpu B & ./cpu C &` → изходът се редува

**Механизъм vs политика**
- Механизъм = *как* (context switch)
- Политика = *какво* (кой процес следва - планировчикът)

**Виртуализация на паметта**
- Всеки процес има собствено **адресно пространство** (виртуални адреси)
- ОС + хардуер превеждат виртуален → физически адрес
- Предимства: **изолация**, удобство, ефективност (**swapping** на диска)
- `./mem & ./mem &` → **един и същ адрес, но различни броячи**
- **ASLR** разбърква адресите за сигурност (`kernel.randomize_va_space=0` изключва, `=2` включва)

### Паралелност

- **Нишките** на една програма споделят една памет
- **Race condition**: `counter++` = прочети + увеличи + запиши → увеличения се губят
- Без заключване: резултатът е различен всеки път и обикновено < 2 × loops
- С **mutex** (`pthread_mutex_lock/unlock`): точен резултат, но по-бавно; само една нишка в **критичната секция**
- **Concurrency** - припокриващи се интервали, може на едно ядро
- **Parallelism** - буквално едновременно, изисква > 1 ядро

### Постоянство

- RAM е нетрайна, дискът е трайен
- **Файловата система** - абстракция над диска (имена вместо сектори/блокове)
- `open`, `write`, `close` - системни извиквания; `fsync` - принуждава данните да стигнат до диска
- `strace ./program` - показва системните извиквания

### Цели на ОС (6)

1. **Абстракция** - лесно създаване и ползване на софтуер
2. **Производителност** - често в конфликт с абстракцията
3. **Сигурност** - основен принцип: изолация
4. **Надеждност** - работи нон-стоп, възстановява се
5. **Енергоефективност** - sleep, hibernate
6. **Преносимост** - x86, ARM; сървъри, телефони

## 3. Компоненти на ОС

### Ядро

- Зареден в защитена памет, работи в **привилегирован режим**
- **Не е постоянно работещ процес** - код, който се извиква при:
	- системно извикване
	- хардуерно прекъсване (таймер)
	- грешка в програма
- Области: процеси и нишки, памет, файлова система, устройства, мрежа, системни извиквания
- В Linux: файл `/boot/vmlinuz-...`; `uname -r`, `uname -a`, `cat /proc/version`

### Драйвери

- Код, който позволява на ядрото да работи с конкретно устройство; крие разликите зад общ интерфейс
- Пример: HDD и SSD работят различно, програмата пише в един и същ файл
- Видове:
	- **символни** - байт по байт (клавиатура, сериен порт, звук)
	- **блокови** - блокове, произволен достъп (HDD, SSD, USB памет)
	- **мрежови** - пакети (мрежова карта)
- Linux: **модули** - зареждат се без рестарт: `lsmod`, `modinfo`, `sudo modprobe`

### Режими на работа

| Режим на ядрото | Потребителски режим |
| --------------- | ------------------- |
| пълен достъп до хардуера и паметта | само собственото адресно пространство |
| ядрото и драйверите | всички останали програми, вкл. шела и GUI |

- Разделението е **в процесора** (специален бит); привилегирована инструкция в потребителски режим → грешка
- **Без ядро** (направо): аритметика, цикли, условия, локални функции, собствена памет
- **Със системно повикване**: файл, устройство, мрежа, друг процес, допълнителна памет
- `printf` → накрая вика `write()`

**Превключване:**
1. Програмата изпълнява **trap** (или възниква прекъсване)
2. Процесорът минава в режим на ядрото и скача на **предварително зададен** адрес
3. Ядрото изпълнява искането
4. Връщане в потребителски режим

> Програмата **не избира** къде в ядрото да скочи → не може да заобиколи защитата.

### Видове ядра

| | Монолитно | Микроядро | Хибридно |
| - | --------- | --------- | -------- |
| В режим на ядрото | всичко (планиране, памет, ФС, драйвери, мрежа) | само минимумът (адресни пространства, базово планиране, IPC) | микроядрена структура + повече услуги в ядрото |
| Комуникация | директни извиквания на функции | **съобщения** (IPC) през ядрото | смесено |
| Скорост | бързо | по-бавно | компромис |
| Срив на драйвер | срива цялата система | рестартира се само сървърът | |
| Примери | Linux, Unix, BSD | Minix, QNX, seL4 | Windows NT, macOS (XNU) |

- Недостатъци на монолитното: голям код, трудно разширяване, по-лоша надеждност
- Linux = монолитно **с модули (LKM)**
- **IPC** в микроядрото: `send` / `receive`; **синхронно** (подателят чака) или **асинхронно** (опашка)
- Бързината на IPC определя бързината на цялата микроядрена система

### Системни повиквания и API

- **Системно повикване** - единственият контролиран начин за услуга от ядрото; номерирани функции
- **API** - функциите, достъпни за програмиста, чрез библиотека (libc)
	- Windows API, **POSIX** (Linux, macOS), Java API
	- предимство: **преносимост** (Linux и macOS имат различни syscall-и, но общо POSIX API)
	- `printf` форматира + буферира → чак тогава `write`
- `write(1, "hi\n", 3)` (libc) ≡ `syscall(SYS_write, 1, "hi\n", 3)` (директно)
- **System-call interface** - свързва API със системните повиквания; номерът е индекс в таблица на ядрото
- **Стандартна библиотека** (Python `os`, Java `java.io`) - по подразбиране; **API на ОС** - когато липсва функция (`fork`, сигнали), производителност (`epoll`), системен софтуер

**Предаване на параметри:** регистри (най-бързо, ограничено), блок в паметта (адресът в регистър), стек. Linux/Windows - блок или регистри.

**6 вида системни повиквания:**

| Вид | Примери |
| --- | ------- |
| Управление на процеси | `fork`, `execve`, `exit`, `wait`, `kill`, `getpid`, `brk`, `mmap` |
| Управление на файлове | `open`, `close`, `read`, `write`, `lseek`, `stat`, `unlink` |
| Управление на устройства | `open`, `read`, `write`, `ioctl` (устройствата са файлове в `/dev`) |
| Поддържане на информация | `time`, `gettimeofday`, `getpid`, `uname` |
| Комуникация | `socket`, `connect`, `send`, `recv`, `pipe`, `shmget` |
| Защита | `chmod`, `chown`, `setuid`, `getuid` |

### Потребителски интерфейс

- **Не е част от ядрото** - обикновени програми в потребителски режим
- **Команден (shell)**: bash, zsh, fish; шелът прави `fork()` + `execve()`; `echo $SHELL`
- **Графичен**: GNOME, KDE, Windows UI; може да липсва (сървъри)
- GUI - по-лесен; CLI - по-мощен (скриптове, SSH, без екран)

## 4. Linux

### Терминология

- **Linux** - само ядрото
- **GNU/Linux** - ядро + GNU програми и библиотеки (glibc, coreutils, bash, gcc)
- **Дистрибуция** - GNU/Linux + инсталатор + пакетен мениджър + приложения
- `cat /etc/os-release` (дистрибуция), `uname -r` (ядро)
- Многозадачна, многопотребителска, с общо предназначение; написано на C (и малко Rust)

### Версии на ядрото

- **major.minor.revision** - напр. `6.11.2`
- До 2.6: четен minor = стабилна, нечетен = тестова (вече не се ползва)
- Клонове: **mainline** (нови функции, на 2-3 месеца), **stable** (поправки), **LTS** (години поддръжка)

### История

| Година | Събитие |
| ------ | ------- |
| 1969 | **Unix** - Bell Labs, Кен Томпсън и Денис Ричи; пренаписан на C → преносим; комерсиален |
| 1983 | **GNU** проект („GNU is Not Unix“) - Ричард Столман; свободна Unix-подобна ОС |
| 1985 | **Free Software Foundation** - Столман |
| 1987 | **MINIX** - Андрю Танънбаум; учебна, **микроядро**, не е свободна |
| 1991 | **Linux** - Линус Торвалдс, хоби, под GPL; GNU + Linux = първата напълно свободна ОС |
| 1992 | **Дебатът Танънбаум - Торвалдс**: микроядро срещу монолитно |

- GNU има всичко, освен готово ядро (**Hurd** не става готово) → Linux запълва празнината
- **POSIX** - стандарт за интерфейса на Unix-подобните системи

### Свободен софтуер и лицензи

**4 свободи:** стартиране за всякаква цел, изучаване и промяна на кода, разпространение на копия, разпространение на променени версии.
„Free as in freedom, not free beer.“

- **GPL (copyleft)** - променена версия трябва да е под същия лиценз + с изходен код
- Linux ядрото: **GPL-2.0**
- **MIT** - много по-свободен (позволява затваряне)
- **Свободен софтуер** (FSF) - акцент върху свободите; **OSS** - акцент върху практическите ползи; заедно **FOSS**
- Предимства на OSS: разпределено сътрудничество, бързо откриване на грешки, развитие според нуждите

### Дистрибуции

- **Linux From Scratch** - всичко сам; не се препоръчва
- Дистрибуцията предоставя:
	1. **Инсталация** - предварително конфигурирани компоненти, автоматичен инсталатор
	2. **Init система** - първият процес, **PID 1** (systemd, openrc, runit); `ps -p 1`
	3. **Пакетен мениджър** - обикновена програма в потребителски режим
	4. **Desktop environment** - GNOME, KDE, XFCE

| Семейство | Мениджър | Дистрибуции | Инсталиране |
| --------- | -------- | ----------- | ----------- |
| Debian | apt | Debian, Ubuntu, Mint | `sudo apt install htop` |
| Red Hat | dnf | Fedora, RHEL, Rocky | `sudo dnf install htop` |
| Arch | pacman | Arch, Manjaro | `sudo pacman -S htop` |

- **Пакет** = софтуер + метаданни (име, версия, зависимости); пази се в хранилище

| Fixed Release | Rolling Release |
| ------------- | --------------- |
| нови версии на определен период | постоянни ъпдейти, без версии |
| добре тествано, стабилно | най-новите пакети, може да се счупи |
| LTS версии | |
| Ubuntu, Debian, Fedora | Arch |
| за обикновени потребители и сървъри | за опитни потребители |

### Предимства и недостатъци

- Популярност: ~4% десктоп, мнозинство сървъри/облак, всички Top500, Android, вградени
- **Предимства**: намаляване на риска (кодът остава ваш, ако доставчикът изчезне), бизнес нужди, стабилност и сигурност, гъвкавост (x86/ARM, от рутери до суперкомпютри), персонализиране, лесна подкрепа (`man`, Arch Wiki), по-ниски разходи
- Отвореният код **не гарантира** сигурност - пример: backdoor в `xz` (2024)
- „Linux е безплатен, ако не си цениш времето“ - TCO не е нула
- **Недостатъци**: съвместимост на софтуера, фрагментация, крива на учене, поддръжка на хардуер

## 5. Команди за запомняне

```bash
uname -r                     # версия на ядрото
uname -a                     # информация за системата
cat /proc/version            # как е компилирано ядрото
cat /etc/os-release          # коя дистрибуция
lsmod                        # заредени модули
modinfo <име>                # информация за модул
sudo modprobe <име>          # зареждане на модул
strace ./program             # системни извиквания на програма
echo $SHELL                  # текущият шел
ps -p 1                      # процесът с PID 1 (init)
gcc -o main main.c           # компилиране
./cpu A & ./cpu B &          # стартиране на процеси във фонов режим
kill %1 %2                   # спиране на фоновите задачи
sudo sysctl -w kernel.randomize_va_space=0   # изключване на ASLR
```

## 6. Чести капани

- **PC** е адресът на *следващата* инструкция, **IR** - на *текущата*
- Байтът е най-малката *адресируема* единица, битът - най-малката *единица*
- Адрес с m бита → **2^m** клетки, не m клетки
- Ядрото **не** е процес, който работи постоянно
- Фърмуерът е на **дънната платка**, boot loader-ът е на **диска**
- Шелът, GUI и пакетният мениджър **не** са част от ядрото
- `printf` **не** е системно повикване - то вика `write`
- Linux е **монолитно** ядро (модулите не го правят микроядро); Windows и macOS - **хибридни**
- MINIX е **микроядро** и **не** е свободен софтуер
- Свободен ≠ безплатен; GPL ≠ MIT
- Concurrency е възможна на едно ядро, parallelism - не
- Еднакъв виртуален адрес в два процеса ≠ еднаква физическа памет

### II част - ключови точки

**11.** 7-те стъпки на FDE (виж т. 1). Прекъсване - сигнал за събитие от хардуер (I/O, таймер) или софтуер (грешка, syscall). Проверка след всяка инструкция. Обработка: запазване на състоянието → interrupt handler → изпълнение → възстановяване.

**12.** Програма - пасивен файл; процес - изпълняваща се програма с ресурси. Time sharing + context switch + планировчик. Хардуерен таймер генерира прекъсване и връща управлението на ядрото. Всеки процес има свое адресно пространство; ОС превежда виртуалния адрес до различни физически.

**13.** Таблицата в т. 3. Примери: Linux / Minix (QNX, seL4) / Windows NT (macOS). Монолитно: + бързо, − срив на драйвер срива системата. Микроядро: + надеждност/сигурност, − по-бавно (IPC). Linux - LKM модули (`modprobe`).

**14.** Цикълът и смятането - направо в потребителски режим; `printf` → системно повикване `write()`. Trap → режим на ядрото, скок на предварително зададен адрес → изпълнение → връщане. API (libc, POSIX) - удобен, преносим слой; системното повикване - реалната врата към ядрото. `strace ./program`.

**15.** Терминологията от т. 4. Unix (1969, Bell Labs) → GNU (1983, Столман, свободен софтуер, без готово ядро) → MINIX (1987, Танънбаум, учебно микроядро, несвободно) → Linux (1991, Торвалдс, GPL). Дистрибуцията дава: инсталатор, init система, пакетен мениджър, desktop environment. Fixed - стабилност (сървъри, обикновени потребители); Rolling - най-новото (опитни потребители).
